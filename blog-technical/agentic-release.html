Product · Release announcement

Announcing the Akka Agentic Platform.

Four integrated offerings — Orchestration, Agents, Memory, and Streaming — for every shape of agentic system: autonomous, adaptive, real-time, transactional, or edge. Delivered on the same runtime that already carries more than a billion tokens a second in production.

Akka Product Team · Release notes
July 10, 2024 · 8 min read

Years of customer collaboration have shaped this release. Akka has been running scalable agentic systems in production for those customers, with the top-scale customer now processing more than a billion tokens per second. The offerings introduced today are the pieces those systems asked for. All four are available immediately and are included in every existing Akka license.

What's new Four offerings, a native local console, an AI-assisted DevEx, a testkit, and a preview of the evaluation console (later this summer).

The four offerings compose. They are the runtime primitives a production agentic system needs, delivered as a single SDK, a single deployment target, and a single operations model. Each covers a job most teams currently assemble from three or four external services.

All four offerings sit on the same runtime.

Section II · The developer experience

A local console, an AI-assisted DevEx, and a testkit.

Alongside the four offerings, the SDK now ships a native binary local console for executing distributed services during development and tracing agentic interactions. Docker is no longer a console requirement. The console is available through the Akka CLI.

The AI-assisted DevEx uses event-driven component composition, with support for Qodo, Windsurf, and Cursor. LLM-authored agents create, modify, test, and evaluate Akka services built with the SDK. The Agent Testkit builds unit, integration, and multi-agent system tests that run locally or inside CI/CD, mimicking the production environment. Custom evaluation strategies automate testing of non-deterministic LLM interactions.

Coming later this summer An agentic evaluation console with separate flows for development, operations, and context engineering. Traces span networks and Akka components, even when components are separated by event-driven decoupling. Every trace carries performance, functional, and cost intelligence.

Section IV · Design goals

Production-ready. Elastic. Batteries-included.

  1. Production-ready. Agents work identically in development and production without code changes. The runtime targets 99.9999% uptime regardless of scale.
  2. Elastic. Agents process over a billion tokens per second with consistent latency, bounded only by the model itself.
  3. Batteries-included. One SDK and one runtime, with orchestration, agents, memory (short and long-term), and streaming already inside.

Three axes of comparison: velocity, compute, SLA.

With Akka
With others you…
One DevEx to build, test, integrate, and upgrade agentic systems. Composable components, rapid development, visual debuggers, no-downtime rolling updates.
Cobble together four SDKs, each with its own DevEx. Add an integration testing system. Deploy four architectures (orchestration, memory, agents, streaming) where coordinated rolling updates become near-impossible.
Shared-compute execution model. The concurrency and non-blocking event architecture drive utilization toward 100%. Every core Akka consumes reduces total infrastructure spend.
Separate compute allocation and utilization across four runtimes — orchestration, memory, agents, streaming — with multi-threading that blocks and locks. Waste compounds further on Python runtimes.
Services self-cluster to millions of nodes and adapt to hardware failures, network partitions, LLM hallucinations, or shifting environments. Services are their own system of record — data sharded, in-memory, and replicated, independent of a database.
Delegate SLA achievement to cloud infrastructure, databases, or messaging brokers that have no visibility into the application's intent. No built-in data replication, failover, or DR — assurance requires full-stack duplication.
